# Сервер «Отряда»

Сервер хранит забеги, сам проводит бои и подбирает соперников из отрядов других игроков. Клиент только показывает игру: он присылает действия хода, сервер повторяет их тем же ядром (`packages/core`) и не доверяет результату клиента.

## Как это работает

1. Mini App открывается, клиент берёт подписанные Telegram данные запуска (`initData`) и шлёт их в заголовке `Authorization: tma <initData>`.
2. Сервер проверяет подпись токеном бота. Пароли и регистрация не нужны.
3. В лавке клиент применяет действия у себя для мгновенного отклика и копит их.
4. По кнопке «В бой» клиент отправляет действия хода. Сервер:
   - восстанавливает забег из базы и повторяет действия;
   - отклоняет запрос, если какое-то действие нарушает правила;
   - подбирает отряд-призрак того же раунда с близким числом побед;
   - проводит бой, сохраняет забег, а отряд игрока записывает призраком для других.
5. Если запрос отклонён, клиент берёт состояние с сервера.

Защита от двойной отправки: у забега есть версия, и ход со старой версией получает ответ 409.

Если сервер недоступен или игра открыта не в Telegram, клиент играет офлайн, как раньше.

## Дуэли

После забега игрок жмёт «Побей мой отряд» и отправляет ссылку в любой чат. Друг открывает её, видит отряд вызвавшего и проходит свой забег с того же зерна, то есть с той же первой лавкой. По ходу забега он бьётся с обычными соперниками, а после последнего боя его финальный отряд сражается с отрядом вызвавшего. Результат сохраняется, вызвавший получает сообщение от бота (если он когда-нибудь писал боту) и видит ответ в игре.

## Рейтинг чата

Когда игру открывают по ссылке из группы, Telegram передаёт `chat_instance`: постоянный идентификатор этого чата. Забег, начатый так, привязывается к чату. На экране итога показывается лучший результат каждого участника за 7 дней среди забегов из этого чата. Боту не нужно быть в группе.

Для проверки без Telegram: `?dev=<id>@<чат>` при `DEV_AUTH=1`.

## API

| Запрос | Что делает |
|---|---|
| `GET /api/health` | проверка, что сервер жив |
| `GET /api/me` | имя игрока и статистика |
| `GET /api/runs/current` | текущий забег или `null` |
| `POST /api/runs` | новый забег (старый закрывается); `{ duel: код }` — ответ на вызов, `{ daily: true }` — вызов дня (одна попытка, повтор → 409) |
| `POST /api/runs/:id/turn` | `{ version, actions }` → новое состояние, бой, имя соперника; в последнем ходе забега-дуэли ещё и бой с отрядом вызвавшего |
| `POST /api/runs/:id/duel` | сделать вызов из оконченного забега → код и ссылка `t.me/…?startapp=d_<код>` |
| `GET /api/duels/:code` | кто вызывает, сколько побед, его отряд |
| `GET /api/duels` | последние ответы друзей на ваши вызовы (новые помечаются прочитанными) |
| `GET /api/daily` | вызов дня: дата (по Москве), статус игрока `none`/`active`/`finished`, топ-10 и место игрока |
| `GET /api/profile` | рыбки, рамки, задания дня и сезонный путь; выполненные задания и уровни сезона оплачиваются здесь, каждый один раз |
| `POST /api/shop/buy` | `{ item }` купить рамку за рыбки и сразу надеть |
| `POST /api/shop/equip` | `{ item }` надеть купленную рамку, `null` вернуть обычную |
| `GET /api/league` | недельная лига: лига игрока, очки, сколько забегов зачтено сегодня, место, топ-10, сколько мест уходит вверх и вниз |
| `GET /api/chat` | рейтинг чата за неделю, если игра открыта из группы (иначе `null`) |

Ограничение: 120 запросов в минуту на игрока.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN` | проверка подписи игроков, обязательна |
| `DATABASE_URL` | PostgreSQL; без неё данные в памяти и пропадают при перезапуске |
| `CORS_ORIGIN` | адреса клиента через запятую, если клиент живёт не на сервере (например `https://biktorb.github.io`) |
| `STATIC_DIR` | папка собранного клиента, чтобы сервер отдавал и игру |
| `TELEGRAM_APP_LINK` | ссылка на Mini App (`https://t.me/<бот>/<приложение>`) для вызовов; по умолчанию в `docker-compose.yml` стоит ссылка игры |
| `TELEGRAM_API_BASE` | адрес посредника для Bot API, если сеть сервера блокирует `api.telegram.org` (см. ниже); по умолчанию `https://api.telegram.org` |
| `PORT` | порт, по умолчанию 3000 |
| `DEV_AUTH=1` | только для разработки: вход заголовком `dev <id>` (или `dev <id>@<чат>`) без Telegram |

Токен бота храните только в переменных окружения или `.env` на сервере, никогда в репозитории.

## Локальный запуск

```sh
# PostgreSQL на localhost с базой otryad
DATABASE_URL=postgres://otryad:otryad@localhost/otryad DEV_AUTH=1 \
CORS_ORIGIN=http://localhost:5173 npm start -w @otryad/server

# клиент, который ходит в этот сервер
VITE_API_URL=http://localhost:3000 npm run dev
# открыть http://localhost:5173/?dev=1
```

Тесты на PostgreSQL: `TEST_DATABASE_URL=postgres://… npm test` (без переменной тесты идут только на хранилище в памяти).

Нагрузочная проверка против сервера с `DEV_AUTH=1`: `node tools/load.ts http://localhost:3000 200 5`.

## Развёртывание на VPS

Нужен VPS с Ubuntu или Debian (хватит 1 vCPU и 1 ГБ памяти) и открытые порты 80 и 443. Свой домен не обязателен: по умолчанию игра получает адрес `IP-сервера.sslip.io` (например `203-0-113-7.sslip.io`), и Caddy сам выпускает для него HTTPS-сертификат.

1. Зайти на сервер по SSH и выполнить:
   ```sh
   curl -fsSL https://raw.githubusercontent.com/biktorb/tlelgram_test/main/deploy/install.sh | sudo bash
   ```
   Скрипт ставит Docker, добавляет 2 ГБ подкачки (сборке не хватает 1 ГБ памяти) и скачивает код в `/opt/otryad`. Затем он спрашивает домен и токен бота: токен вводится скрыто и сохраняется только в `/opt/otryad/.env`. После этого скрипт запускает PostgreSQL, сервер и Caddy и сам проверяет, что игра отвечает по HTTPS.
2. В @BotFather: `/myapps` → приложение → Edit Web App URL → адрес, который напечатал скрипт. Сервер отдаёт и игру, и API с одного адреса.
3. Обновление до новой версии: та же команда ещё раз или автообновление (ниже).

### Автообновление после каждого слияния в main

После того как CI прошёл на main, GitHub Actions («Deploy server») заходит на сервер по SSH и запускает `deploy/update.sh`: скачивает код, пересобирает и перезапускает игру, проверяет HTTPS. Настраивается один раз:

1. На сервере: `sudo bash /opt/otryad/deploy/enable-autodeploy.sh`. Скрипт создаёт отдельный SSH-ключ, который может только запускать `update.sh` (консоль и другие команды ему недоступны), и печатает, что вписать в GitHub.
2. В GitHub: Settings → Secrets and variables → Actions. Secret `DEPLOY_SSH_KEY` — напечатанный ключ, variable `DEPLOY_HOST` — IP сервера.

Пока секрет не задан, шаг деплоя пропускается. Запустить обновление вручную можно во вкладке Actions → Deploy server → Run workflow. Отозвать доступ: удалить строку `otryad-deploy` из `/root/.ssh/authorized_keys`.

Полезное на сервере:
```sh
cd /opt/otryad
docker compose ps                  # что запущено
docker compose logs --tail 50 server
docker compose exec db pg_dump -U otryad otryad > backup.sql   # резервная копия базы
```

Вариант без переноса клиента: оставить игру на GitHub Pages, задать в репозитории переменную `API_URL` (Settings → Secrets and variables → Actions → Variables) с адресом сервера и перезапустить «Deploy prototype». Сервер по умолчанию разрешает запросы с `https://biktorb.github.io`.

### Если сервер не достаёт до Telegram

Игре связь с Telegram не нужна: подпись игрока проверяется на сервере. Связь нужна только для сообщений бота, то есть для уведомлений о принятых вызовах и напоминаний. Проверить связь можно так:

```sh
curl -4 -sS -m 10 -o /dev/null -w "%{http_code}\n" https://api.telegram.org/
```

Ответ `302` означает, что связь есть. Таймаут означает, что хостер блокирует Telegram. Тогда запросы можно пускать через бесплатный Cloudflare Worker:

1. На dash.cloudflare.com откройте Workers & Pages → Create → Create Worker, назовите его, например, `otryad-tg` и нажмите Deploy.
2. Нажмите Edit code и вставьте содержимое `deploy/telegram-relay.js`. В `BOT_ID` впишите число до двоеточия из токена бота: оно не секретное. Нажмите Deploy.
3. На сервере добавьте адрес Worker в `.env` и перезапустите:
   ```sh
   cd /opt/otryad
   echo 'TELEGRAM_API_BASE=https://otryad-tg.<ваш-поддомен>.workers.dev' >> .env
   docker compose up -d
   ```

Чтобы проверить работу посредника, отправьте вызов другу. Когда друг доиграет, бот пришлёт вам сообщение. Ошибки отправки видны в `docker compose logs server | grep notification`.

## Проверено (25.10.2026)

- 39 автотестов: проверка подписи Telegram, полный ход, двойная отправка, недопустимые и поддельные действия, чужой забег, призраки. Отдельный тест сверяет клиент и сервер на случайной игре в лавке, расхождений нет. Всё прогоняется и на памяти, и на PostgreSQL.
- Полный забег в браузере через сервер: 10 ходов, все приняты.
- 200 игроков одновременно по 5 ходов: 1200 запросов за 1,8 с, p95 460 мс, ошибок нет.
- Забеги переживают перезапуск сервера.
- Docker-образ собирается, применяет миграции, засевает 746 отрядов-ботов и отдаёт игру.
- Связка из `docker-compose.yml` (PostgreSQL, сервер, Caddy) запущена целиком: игра и API отвечают по HTTPS, HTTP перенаправляется на HTTPS.

Известное ограничение: состояние генератора случайных чисел лавки есть у клиента, поэтому теоретически можно заранее узнать, что выпадет при обновлении лавки. Бой при этом считается только на сервере. Если это станет проблемой, обновление лавки можно перенести на сервер.
